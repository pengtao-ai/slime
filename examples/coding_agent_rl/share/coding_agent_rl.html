Why

Coding-Agent RL 难在哪：从「可验证答案」到「可验证轨迹」

单轮 Math/Code RLVR 的信用分配近似等于整段 response；SWE agent 把同一问题拆成数十 turn 的工具环，结局稀疏、中间不可直接评分。

单轮 RLVR

  • 一次采样 → 一次可验证奖励（对/错）
  • credit ≈ 整段 response 广播
  • 无长期工具环；状态短
  • GRPO / RLOO 广播通常够用
  • 失败样本仍有「答错」的清晰信号

SWE Coding-Agent

  • 数十 turn：Read / Edit / Bash / Grep / Agent…
  • 稀疏终局：patch 测过才 0/1（大量失败轨迹）
  • 黑盒 harness + 白盒 token（Adapter 捕获）
  • subagent / compaction → fan-out 多 Sample
  • 可选 mid-turn offload（SLM↔GLM）改变成本结构
本讲主线
稀疏结局 R(τ) → shaping 得到 turn 级 r_i → GRPO A_s → turn paint → fan-out 归一 → loss_mask。再对照 GiGPO-SWE（diff 聚类）与 ARPO（熵分支）。
Architecture

系统总览：从 JSONL 到权重更新

真实 coding agent 在沙箱修 bug → Adapter 捕获每轮 token/logprob → 协议验题 shaping → GRPO（+ turn paint）更新 SLM；可选 mid-turn offload。

Takeaway

带走五句话

  1. 协议决定验题：ScaleSWE 新箱 patch vs Tmax 同箱终态，防作弊点不同。
  2. Credit 是多层的：结局 shaping → turn paint → fan-out 归一 → loss_mask。
  3. 对照清接口：Turn-paint（落地）· GiGPO （anchor state）· GiGPO-diff（方案）· ARPO（熵分支）。
  4. 口径分开：强模型 harness pass@1 ≠ RL 训练 mean_reward。
  5. 实现真相：fan-out 全额 reward + mask 归一；以代码为准，不以旧 README 为准。
